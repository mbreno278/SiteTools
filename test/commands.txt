
# ETAPA 2 — ARQUITETURA E CLEAN CODE

Prioridade: ALTA.

O objetivo é evoluir gradualmente a arquitetura existente sem reescrever todo o projeto.

Avalie a utilização de uma arquitetura em camadas.

Estrutura de referência:

app/
    Controllers/
    Models/
    Repositories/
    Services/
    Helpers/
    Middleware/
    Exceptions/

config/

routes/

resources/
    views/
    css/
    js/

storage/

public/

tests/

A estrutura deverá ser adaptada à realidade do projeto. Não mova todos os arquivos indiscriminadamente.

## 2.1. Controllers

Os Controllers deverão:

- Receber requisições.
- Validar os dados de entrada.
- Coordenar os serviços.
- Definir respostas HTTP.
- Não concentrar regras de negócio.

## 2.2. Services

Centralize regras de negócio em serviços específicos.

Exemplos:

- ToolAccessService.
- DocumentConverterService.
- ImageProcessingService.
- FileStorageService.
- PaymentService.
- UserService.
- UsageLimitService.

## 2.3. Repositories

Centralize operações de banco de dados.

Evite espalhar consultas SQL idênticas em diversos arquivos.

Utilize PDO e consultas preparadas.

## 2.4. Helpers

Mantenha nos Helpers apenas funções auxiliares reutilizáveis.

Evite transformar Helpers em arquivos que concentram regras de negócio.

## 2.5. Tratamento de erros

Crie um padrão de tratamento de erros.

As respostas JSON deverão possuir estrutura consistente.

Exemplo:

{
    "success": false,
    "message": "Não foi possível processar o arquivo.",
    "data": null
}

Não exponha stack traces, caminhos internos, credenciais ou detalhes do servidor ao usuário.

Registre detalhes técnicos em logs seguros.

# ETAPA 3 — BANCO DE DADOS

Prioridade: ALTA.

Analise o dump atual e compare todas as tabelas com as consultas utilizadas pelo código.

Não recrie tabelas existentes sem necessidade.

## 3.1. Integridade referencial

Revise os tipos das colunas:

- users.id
- user_id
- tools.id
- tool_id
- payment_id

Padronize os tipos das chaves relacionadas.

Verifique os mecanismos de armazenamento.

Converta tools de MyISAM para InnoDB, após verificar compatibilidade e realizar backup.

## 3.2. Chaves estrangeiras

Avalie e implemente relacionamentos entre:

- users e user_favorites.
- users e user_tool_access.
- users e user_payments.
- users e user_files.
- tools e user_favorites.
- tools e user_tool_access.
- tools e user_tool_usage.
- user_payments e user_tool_access.

Defina regras adequadas de exclusão e atualização.

Não utilize ON DELETE CASCADE indiscriminadamente.

## 3.3. Categorias

Revise a utilização de:

- tools.category
- tools.category_id
- categories

Consolide a classificação das ferramentas utilizando categories como fonte principal.

Crie uma migração que preserve os registros existentes e trate valores duplicados ou semelhantes.

## 3.4. Controle de acesso

Revise:

- tools.access_type
- tool_access_rules
- user_tool_access

Defina claramente a diferença entre:

- Disponibilidade operacional.
- Autenticação necessária.
- Modalidade comercial.
- Autorização temporária.

Evite manter duas fontes de verdade para a mesma regra.

## 3.5. Pagamentos

Revise user_payments.

Prepare o banco para:

- Pagamentos pendentes.
- Pagamentos aprovados.
- Pagamentos recusados.
- Estornos.
- Cancelamentos.
- Concessão automática de acesso.
- Renovação de acesso.
- Histórico de transações.

Implemente uma estrutura para registrar eventos de webhook com identificadores únicos e processamento idempotente.

Nunca conceda acesso pago somente porque o navegador informou que o pagamento foi concluído.

A confirmação deverá ocorrer por comunicação validada com o provedor de pagamentos.

## 3.6. Histórico e limites

Revise:

- tool_usage.
- user_tool_usage.
- tool_usage_limits.
- tool_usage_counters.

Defina claramente a diferença entre estatísticas gerais e histórico pessoal.

Implemente limites reais no servidor.

Considere utilização anônima e autenticada.

Evite depender exclusivamente de endereço IP para identificar visitantes.

## 3.7. Migrações

Todas as alterações deverão ser realizadas por scripts SQL incrementais.

Nunca executar um dump contendo DROP TABLE como procedimento de atualização.

Antes de cada migração:

1. Gerar backup.
2. Verificar os dados existentes.
3. Executar a migração.
4. Conferir a integridade.
5. Registrar a versão aplicada.

Cada ferramenta poderá possuir seu próprio acesso pago e temporário.

Implemente corretamente:

- Liberação após confirmação do pagamento.
- Data de início.
- Data de expiração.
- Renovação.
- Cancelamento.
- Suspensão.
- Histórico de acessos.

O acesso gratuito deverá continuar disponível sem obrigar o visitante a criar uma conta.
